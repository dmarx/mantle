# ADR-008: A render crash leaves a way out, optional engines load behind a probe, and fetching is honest about why it failed

## Context

[ADR-001](ADR-001.md) R7 says a blank page is not a state. strata-g shipped one: a
dependency touched the GPU at module scope, before any error boundary
existed, so a browser with WebGL blocklisted got nothing ([SG-ADR-226](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-226.md)).

mantle will load a 4.4 MB gzipped wasm database engine for views. R8 rules
out cross-origin isolation, so some wasm features are unavailable. And
mantle fetches every document across the network, from the deployed site or
from `raw.githubusercontent.com`.

strata-g's browser-direct fetching ([SG-ADR-113](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-113.md), [SG-ADR-195](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-195.md), [SG-ADR-120](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-120.md))
met each failure mode mantle will: CORS, rate limits, partial loads. The
owner runs all of it there today ([ADR-005](ADR-005.md)).

## Decision

*Proposed.*

**A way out of every crash:**

- The app mounts inside a boundary that renders any uncaught error, with its
  cause, into the page.
- Top-level `error` and `unhandledrejection` handlers do the same for what
  escapes the boundary.

**Optional engines behind a probe.** Code that needs a capability not every
browser has is loaded only by dynamic `import()`, after a probe for the
capability. That covers the LadybugDB wasm engine and any graph renderer.
A failed probe says what is missing, and the rest of the site works without
it. Reading a document never depends on an optional engine.

**Honest fetching** behind the one `fetchDocument` seam ([DP-012](../../docs/design-principles.md#dp-12)):

- **Typed failures.** A failure is one of CORS-blocked, offline, HTTP
  status, rate-limited or malformed, and is shown as such. A `no-cors` probe
  tells CORS apart from offline. A non-OK response becomes a readable
  message, never a `.json()` SyntaxError.
- **Rate limits.** On 429 or 503, honour `Retry-After`, else back off with
  jitter. Cap concurrent requests per host.
- **Cancellation.** An `AbortSignal` runs through every leaf fetch, so
  navigating away cancels the loads it no longer needs ([SG-ADR-118](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-118.md)).
- **Where bodies come from.** Document bodies come from
  `raw.githubusercontent.com` at a pinned commit (CORS-open, outside the
  REST API's 60-an-hour anonymous budget), never from the REST contents API.
- **Partial loads.** A load that can't complete is refused with the count of
  what loaded. It isn't presented as complete.

## Alternatives considered

- **Static imports of optional engines.** The bundle is simpler, and one
  missing capability takes down the whole page.
- **One generic "failed to load" message.** It is accurate and useless. The
  reader can't tell their network from the host, and the owner can't tell a
  rate limit from a bug.
- **Fetching through the GitHub REST API.** It is rate-limited to 60
  anonymous requests an hour, which a single large view exceeds.

## Consequences

- The first code pull request carries the boundary, the handlers and
  `fetchDocument` with its failure types, before any feature uses them.
- A test opens a fixture whose document URL returns 404, and asserts
  `data-render-state="error"` with the status in the reason.
