# ADR-009: The renderer ships as a custom element with sanitized markdown, accessibility rules are fixed from the start, and the shell says what version it is

## Context

[ADR-001](ADR-001.md) R5 asks for one markdown pipeline, shared by the shell and anything
else that shows a record in a browser.

strata-g solved the same embedding problem with a self-contained viewer: a
custom element in a shadow root, serving both a whole-document export and
embed snippets, with host and viewer styles unable to reach each other, and
embedded data escaped against injection ([SG-ADR-237](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-237.md), [SG-ADR-238](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-238.md)). It also
retrofitted about 50 accessibility gaps before writing its rules down
([SG-ADR-151](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-151.md)). And it versions what it ships, and shows the version
([SG-ADR-088](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-088.md)).

mantle's manifest is a contract between repositories ([ADR-001](ADR-001.md)), so a
deployed shell has to say which versions it reads. The owner runs all three
in strata-g ([ADR-005](ADR-005.md)).

## Decision

*Proposed.*

**`<mantle-doc>`.** The renderer is a custom element with a shadow root.

- It takes a document source and renders it with the one pipeline ([DP-008](../../docs/design-principles.md#dp-8)).
- It sets `data-render-state` ([ADR-007](ADR-007.md)).
- It sanitizes the HTML it produces, because a producer's markdown is
  untrusted input.

The shell uses it for every page, and any other page can embed it, several
times over. Styles can't cross the shadow boundary in either direction.

**Accessibility rules**, from the first component:

- clickables are real `<button>` or `<a>` elements;
- every control has an accessible name;
- state lives in ARIA attributes, not only in a class;
- dynamic text uses `role=status` or `role=alert`;
- composite widgets follow the WAI-ARIA Authoring Practices;
- native elements come before ARIA (`<dialog>`, `<details>`).

There is no UI kit until a genuinely hard widget needs one.

**The shell says what it is.**

- A root `VERSION` file is canonical, and mantle versions semantically.
- The build bakes the version, the commit and the supported manifest schema
  range into the shell.
- It shows them in the footer, and serves them as `version.json`, so a bug
  report and a producer can both read them.

## Alternatives considered

- **An iframe embed.** It needs its own hosting and fixed sizing, and the
  host page can't size it to its content.
- **Trusting the producer's HTML.** A record is anyone's markdown. One
  `<script>` in a document is a script on the site.
- **A component library from the start.** It brings its own markup and
  accessibility assumptions before mantle has a widget that needs them.
- **No visible version.** "Which mantle built this page?" then has no answer
  but the deploy log.

## Consequences

- `<mantle-doc>` is the first UI component, and the shell is built on it.
- The `VERSION` file and `version.json` land with the first build.
- A Tailwind or similar CSS preflight, if one is ever added, removes
  `<dialog>`'s default centring, as strata-g found. Re-check dialogs then.
