# ADR-001: mantle publishes a markdown tree described by a manifest, rendered in the visitor's browser

## Context

luria publishes a record with Quartz, which renders every page to HTML on
every build. The CI history of the records that publish that way, analysed in
[dmarx/luria#411](https://github.com/dmarx/luria/pull/411), shows the cost:

- nucleation's site step grew from 61 s (2026-09-25) to 2731 s (2026-11-25).
  Over the same period its artifact grew from 8.6 MB to 442.9 MB, and build
  time tracks size closely (r = 0.985, n = 18). Quartz's emit phase was 84%
  of the build.
- Deploys, not builds, have started failing: three `deploy-pages` runs hit
  the 10-minute limit on 360–440 MB artifacts.
- Page weight is unbounded. Every page fetches a full-text index (2.9 MB for
  luria's record), and nothing stops a 4.9 MB single-table view from being
  the page a visitor opens.

The cost is per page, so it grows with every document. Measuring the split
inside Quartz's emit phase is under way (luria's weekly timed build), but the
shape of the problem doesn't depend on that split.

## Decision

*Proposed.* mantle publishes **a shell and a manifest**, and renders in the
browser.

- **The manifest is the interface.** A JSON document listing every page:
  path, title, and optionally an identifier, a kind, a status, typed links to
  other pages, and arbitrary display properties. mantle needs nothing else
  from its producer. luria writes one from its record. A plain directory of
  markdown gets one from `mantle scan`, so mantle is useful with no luria at
  all. The schema is versioned, and mantle refuses, by name, a manifest
  version it doesn't read.
- **Documents are fetched, not prebuilt.** The shell fetches a page's
  markdown when the page is opened, from the deployed bytes or from a raw
  source URL the manifest names (`raw.githubusercontent.com` at a commit),
  and renders it client-side.

**Requirements:**

- **R1, build cost tracks metadata.** A build does work proportional to the
  manifest, or to what changed, never to every page's rendered size. Target:
  a nucleation-sized tree (about 13k documents) builds in under 2 minutes.
- **R2, small deploy.** The artifact is the shell plus whatever can't be
  fetched from the source. Target: under 50 MB at nucleation's size.
- **R3, bounded page weight.** No page load fetches the whole tree. Search
  and graph data are sharded or queried. A document above a size threshold is
  paginated or virtualized. First paint needs only the page asked for.
- **R4, stable URLs.** A page's URL is its source path, the scheme Quartz
  sites already use, so moving a luria record from Quartz to mantle breaks no
  inbound link. Anchors are the producer's (luria owns its slugs).
- **R5, one renderer.** One markdown pipeline renders every page and is the
  one other browser tools embed, so two renderings of a document cannot
  disagree.
- **R6, observable.** The build reports its step durations and output bytes
  by kind on every run, as a machine-readable file, so R1–R3 are checked
  against a series.
- **R7, honest failure.** A page mantle can't fetch or render says so, and
  says why. A blank page is not a state.
- **R8, static hosting only.** It runs on GitHub Pages: no server code and no
  response headers, so no cross-origin isolation.

## Alternatives considered

- **Tune Quartz** (drop social cards, the graph, the content index). A
  constant factor at best: the build still renders every page on every
  merge, so R1 can't be met. It remains the stopgap if mantle takes longer
  than the records' growth allows.
- **Another static generator** (Hugo, Eleventy, MkDocs). Faster per page,
  same shape: every rendered page is still deployed (R2), and the search
  index still covers the whole site (R3).
- **A luria-only publisher inside the luria package.** It would put a
  front-end toolchain in a Python package, and couple the publisher's release
  cycle to the record tool's. Making it a separate project with a manifest
  boundary also makes it usable without luria, which is a requirement.

## Consequences

- A visitor needs JavaScript. The fallback for a no-script reader is a plain
  index of links to the source markdown.
- Search engines index a shell less well than static HTML. Prerendering only
  index pages is a bounded fix if a project needs it.
- The manifest schema becomes a contract between two repositories. mantle
  versions it, and a luria release names the manifest versions it writes.
- Rendering views from a graph database in the browser (luria's LadybugDB
  export, proposed in [dmarx/luria#411](https://github.com/dmarx/luria/pull/411)) is
  a later increment. The first one reads committed markdown views, so it
  needs no new data format.
