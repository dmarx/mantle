# ADR-006: CI job bodies are make targets the workflows call; docs-only changes skip code jobs; artifacts are kept only as long as they are useful

## Context

strata-g arrived at these three rules after three separate costs:

- **Job logic in YAML.** A week-long runner outage meant CI couldn't be run
  anywhere, because the jobs existed only as workflow steps ([SG-ADR-122](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-122.md)).
- **Docs churn running the full matrix.** Record and documentation changes
  far outnumber code changes, and each one ran every code job ([SG-ADR-176](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-176.md)).
- **Artifact storage.** The quota is account-wide, and `if: always()`
  diagnostic uploads plus default retention filled it ([SG-ADR-210](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-210.md),
  [SG-ADR-201](https://github.com/dmarx/strata-g/blob/main/docs/decisions/ADR-201.md)).

mantle has a large record next to its code from the first day, and its
deploy is itself an artifact. Quartz-era deploys of 360–440 MB were half of
[ADR-001](ADR-001.md)'s problem.

The owner runs all three rules in strata-g, so this adoption cites that use
as its application ([ADR-005](ADR-005.md)).

## Decision

*Proposed.*

- **One registry of checks.** Each CI job body is a `make <job>` target in
  the `Makefile`; anything longer than a few lines is a script in
  `scripts/ci/`. `make ci` runs every check that needs no services, and
  `make help` lists the targets. Workflow YAML keeps only infrastructure:
  checkout, toolchains, caches, artifacts, permissions. A new check is a
  target first, wired into a workflow second. The record's own lint stays the
  `luria` command it is.
- **Docs-only changes skip code jobs.** A cheap `changes` job gates the code
  jobs with a path filter written as `'**'` followed by exclusions
  (`record/**`, `docs/**`, `**/*.md`). The two mistakes aren't symmetric: a
  missed exclusion costs one slow run, a missed inclusion ships untested
  code. `.github/**` is never excluded, and a tag push is never docs-only.
  **mantle's own site build is not gated this way**, since publishing the
  record is the point of a docs change.
- **Artifacts:**
  - diagnostic uploads (logs, traces, screenshots) use `if: failure()`;
  - a hand-off between jobs gets `retention-days: 1`;
  - build reports ([ADR-001](ADR-001.md) R6) keep 90 days, matching luria's `site-perf`;
  - nothing that duplicates committed content is uploaded;
  - anything published per pull request (a preview) is deleted when the pull
    request closes, by a workflow added in the same pull request as the
    preview.

## Alternatives considered

- **Job bodies in YAML.** Fine until CI is the only place a check can run.
  Then "run what CI runs" means reading YAML and retyping it.
- **`npm run` scripts as the registry.** Workable for the TypeScript half, but
  the record's checks are Python, and `make` is the one entry point both can
  share.
- **An inclusion-list path filter** (`src/**`, `tests/**`). Every new code
  directory silently drops out of CI until someone notices.

## Consequences

- The first code pull request adds the `Makefile`, `make ci` and the
  `changes` job together.
- A workflow step longer than a line or two is a smell to move into a
  target.
