**Going wrong, found by the owner.** The survey of sibling records (the
entry of 2026-11-26 19:23) held about a dozen code conventions "for the
first code pull request". The reason given was [NU-ADR-071](https://github.com/dmarx/nucleation/blob/main/record/decisions.d/ADR-071.md)'s rule that a
decision goes with its first application. The owner pointed out that the
rule's purpose was already met: the same developer runs every one of these
conventions in strata-g, so their use has been witnessed. Re-demonstrating
them in an empty repository proves nothing new. The wrong theory was that
"first application" means first application *in this repository*. [ADR-005](../../record/decisions.d/ADR-005.md)
now says a convention adopted from a sibling record cites its use there, and
the held set is filed as [ADR-006](../../record/decisions.d/ADR-006.md) to [ADR-009](../../record/decisions.d/ADR-009.md).

**Going wrong, the same owner message: stacks.** The earlier [ADR-005](../../record/decisions.d/ADR-005.md), one
pull request per unit, all into `main`, has produced deep pull-request
stacks before. The owner's fix, already working in nucleation's dialectic
sessions, is a session pull request: units squash-merge into the session
branch, and the owner reviews the session as one commit per unit. The
revised [ADR-005](../../record/decisions.d/ADR-005.md) and [SOP-002](../../record/procedures.d/SOP-002.md) record it. Their first application is this
session: dmarx/mantle#2 was the first unit merged that way.

**Worth keeping.** When a rule's literal reading and its purpose come apart,
ask what the rule is for. Here the answer was in the owner's development
history, not in this repository.
