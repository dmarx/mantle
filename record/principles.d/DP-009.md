# DP-009: A measurement that cannot fail is not evidence

Before believing a measurement, make it able to fail. An empty measurement
and an unchanged one look the same: both print zero, both read as a pass.

Why: a check that can't fail passes forever, including on the day it stops
measuring anything. strata-g learned this four times, twice after the wrong
conclusion had been reported. Its three assertions are cheap:

- **observed:** the count of what was measured is non-zero;
- **changed:** where a change is expected, an identical before/after is a
  finding about the instrument, not the code;
- **sensitive:** perturb something the measurement should detect, and
  confirm the reading moves.

Applied here:

- A build-size budget (R2) is checked only after the report shows the build
  saw the expected number of pages.
- A page-weight test (R3) loads a fixture page known to exceed the
  threshold, and asserts pagination engaged, before it asserts anything is
  under budget.
- Build-time series (R6) record the runner and the input size with each
  point, so a flat line can be told apart from a broken probe.

The reviewer's question is not "is this number right?" but **"what would
make this number different?"**
