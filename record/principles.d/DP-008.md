# DP-008: One authoritative implementation, read the same way everywhere

For each behaviour there is one implementation, and every consumer calls
it. A second copy, "just for this case", is a second opinion that will
eventually disagree.

Why: two implementations of the same rule drift, and the drift shows up
where nobody is looking. luria's record states this after a link resolver
and a site generator each spelled link targets their own way.

Applied here:

- **One markdown pipeline** renders every page, in the shell and in anything
  that embeds a document ([ADR-001](../record/decisions.d/ADR-001.md) R5).
- **Path → URL and anchor slugs** are luria's for a luria record. mantle
  reads the anchors the producer wrote rather than re-deriving them.
- **Manifest validation** is one module, used by the build that writes a
  manifest and by the shell that reads one, so the two can't accept
  different files.

The corollary: when a second consumer needs a slightly different behaviour,
add a parameter to the one implementation. Don't fork it.
