# DP-011: A capability isn't generic until it has been demonstrated on more than one consumer

Call a capability generic only after a second consumer has used it.

Why: an interface written for one caller is shaped like that caller by
construction. It compiles, it passes, and its coupling is invisible until
someone else tries it. The second consumer is worth far more than the first.

Applied here:

- **"Usable without luria"** is a claim until a plain directory of markdown
  publishes through `mantle scan` with no luria installed. Until then the
  manifest schema is luria's shape with a general-sounding name.
- The fixture set includes at least two producers (a luria record and a
  plain tree) from the first build, so a luria-only assumption fails a test,
  not a user.
- Display properties a producer passes (status, kind, typed links) are
  rendered generically. A field mantle special-cases by name is a coupling to
  one producer.

The corollary: don't build an abstraction ahead of its second consumer.
Write the concrete case, and generalise when the second one arrives.
