# DP-010: A guard pins the invariant that was violated, not the patch that fixed it

A test written after a bug asserts the property the bug broke. It does not
restate the fix.

Why: reading the diff backwards gives "assert the code calls B". That passes
the day it is written, fails only if someone edits that exact line, and lets
the same bug back in two lines over, through a different call, or in a file
that didn't exist yet. It looks like coverage, and isn't.

Applied here:

- A page that rendered blank is guarded by "every fixture page reaches
  `rendered` or `error` with a reason", not by "this function is now
  awaited".
- A broken link after a path change is guarded by "every link in every
  fixture resolves to a page in the manifest", not by a test of the one
  rewritten path.

The corollary: the invariant guard usually covers more than the bug did,
and it can be failing somewhere else on the day it lands. That is it doing
its job. Fix or list those cases; don't narrow the guard.
