# SOP-001: Close a batch of work

## Purpose

A session's lessons and loose ends are cheapest to file while it is still
loaded. Skipped, a correction the owner made in conversation is gone with
the session, an open branch outlives its purpose, and the review triggers of
[ADR-002](../decisions.d/ADR-002.md) are never evaluated, so they never fire.

## Before you start

- The batch is the session's work: its pull requests, here and in any other
  repository the session touched.
- Have the list of those pull requests' URLs to hand.

## Steps

1. **Read each pull request's state from GitHub, not from memory**: open,
   merged or closed, CI green or red, review comments unanswered.
   *Check:* every pull request in the batch has a state you just fetched.
2. **Make sure nothing is unpushed.** For each repository, compare the local
   branch head with the remote's (`git ls-remote --heads origin <branch>`).
   *Check:* the two SHAs match, or the difference is explained to the owner.
3. **File the retro notes the work calls for.** For each thing that went
   notably right or wrong, file a devlog entry tagged `retro` (`luria new`) in
   the pull request it concerns. For each earmark the owner made, file one
   tagged `retro` and `earmarked`, quoting it.
   *Check:* every correction the owner made this session is either in a note
   or deliberately left out, and you can say which.
4. **Check the review triggers** of [ADR-002](../decisions.d/ADR-002.md) against the batch: a contract
   change used; five or more pull requests; a release or a site moving onto
   mantle; a decision revised soon after landing; a process incident.
   *Check:* for each trigger you can say met or not met, and why.
5. **Report to the owner**: each pull request's state, anything left open
   and why, the notes filed, and which triggers are met with a
   recommendation (retrospective, postmortem or neither). Don't write the
   review unasked.
   *Check:* the report names every trigger that is met.

## Done when

The owner has the report, every branch is pushed or explained, and every
met trigger is either answered by the owner or listed as waiting on them.

## Pitfalls

- **Reporting state from memory.** A pull request read twenty turns ago may
  have merged since. Fetch it in step 1, right before the report.
- **A note only for what went wrong.** [ADR-002](../decisions.d/ADR-002.md) asks for what went right as
  well, so that it is kept on purpose.
- **Treating a shallow clone's missing tracking ref as an unpushed branch.**
  `git status` can show no upstream when the remote branch exists. Compare
  SHAs with `ls-remote`, as in step 2.
